# VoiceEmotionApp

Windows-приложение для определения одной из четырёх эмоций в русской речи: радость, грусть, злость или спокойствие. Принимает WAV/MP3, папку записей или звук с микрофона. Показывает распознанный текст, вероятности классов и предупреждение при низкой уверенности.

Аудио обрабатывается локально. Сервер и API для работы приложения не нужны.

## Установка

Нужны Windows, Python 3.11 и интернет для первой установки зависимостей и загрузки внешних моделей. Рекомендуется несколько гигабайт свободного места: `emotion2vec+ base` занимает около 1,1 ГБ, `faster-whisper small` — около 460 МБ. Они скачиваются при первом распознавании; сам классификатор уже лежит в `models/model_v11_dusha_62k.pkl`.

1. Скачайте репозиторий через **Code → Download ZIP** и распакуйте его либо выполните `git clone https://github.com/potrox/VoiceEmotionApp.git`.
2. В папке проекта запустите `install.bat`. Дождитесь сообщения `Done: dependencies are installed and available`.
3. Запустите `run.bat`. При первом запуске модель из `models/` выбирается автоматически. На вкладке «Главная» должен отображаться путь к ней.

Установка создаёт отдельное Python-окружение в `%LOCALAPPDATA%\VoiceEmotionApp\venv-py311`. Папки с кэшем и пользовательскими файлами создаются локально и не входят в репозиторий.

## Распознавание

1. Откройте вкладку «Распознавание» и нажмите «Распознать WAV/MP3-файл». Для нескольких файлов используйте «Пакетное распознавание папки»; CSV с результатами появится в `exports/`.
2. Опция «Создавать транскрипт автоматически» включена по умолчанию. При первом использовании скачивается модель ASR. Если текст уже известен, вставьте его в поле «Транскрипт»: для выбранного файла он имеет приоритет над ASR.
3. Чтобы записать голос, выберите микрофон, нажмите «Начать запись с микрофона», затем «Закончить запись». Длинная запись разбивается на отрезки; результат каждого виден в таблице.

Если ASR не вернул текст, приложение сообщает об этом и использует только аудиомодель. При слабой уверенности оно показывает предупреждение, но не подменяет класс. Оценка эмоции — предположение модели, а не надёжное определение состояния человека.

Загружайте `.pkl` только из доверенного источника: формат `joblib/pickle` может выполнять код при открытии. SHA-256 модели из этого репозитория: `8514637098edf946639e387d895b51ea478608ab49fa605fc3552d798c9c43d0`.

## Обучение на своих записях

Вкладка «Обучение» — отдельный режим для моделей на 104 акустических признаках: Logistic Regression, Random Forest и MLP. Она **не переобучает** поставляемый мультимодальный v11-классификатор. Чтобы запустить этот режим:

1. Подготовьте CSV с колонками `file_path`, `emotion`, `speaker_id`, `dataset_split`. Значения `emotion`: `joy`, `sadness`, `anger`, `calm`; `dataset_split`: `train` или `test`. Один диктор не должен встречаться в обоих наборах. Пути к аудио могут быть абсолютными или относительными к CSV.
2. Во вкладке «Датасет» нажмите «Выбрать CSV» и дождитесь проверки записей.
3. Во вкладке «Обучение» выберите модели и нажмите «Запустить выбранное обучение». Приложение покажет метрики, сохранит bundle в `models/`, отчёт в `reports/` и историю в локальной базе данных.

Пример CSV:

```csv
file_path,emotion,speaker_id,dataset_split
audio/001.wav,joy,speaker_001,train
audio/002.wav,calm,speaker_002,test
```

Схема подготовки корпуса Dusha и скрипт выделения сбалансированной подвыборки описаны в [DATASET_GUIDE.md](DATASET_GUIDE.md). Аудиофайлы и исходные транскрипты в репозиторий не включены.

## Поставляемая модель и качество

Файл `models/model_v11_dusha_62k.pkl` содержит две обученные классифицирующие ветви: Logistic Regression поверх замороженных 768-мерных признаков `emotion2vec+ base` и char TF-IDF + Logistic Regression по транскрипту. Итоговые вероятности складываются с весами 0,4 для аудио и 0,6 для текста. Веса исходного `emotion2vec` и ASR в bundle не включены — их загружают соответствующие библиотеки.

Обе ветви обучены на 62 000 записях official-train части Dusha, по 15 500 на класс; записи official-test в обучение не входили. Разделение и кросс-валидация учитывают `speaker_id`.

| Проверка | Accuracy | Macro F1 |
|---|---:|---:|
| Grouped OOF на train, с эталонным транскриптом | — | 0,7044 |
| Повторная проверка на 3000 official-test записях, с эталонным транскриптом | 0,7113 | 0,7054 |
| Те же 3000, только аудио | 0,5813 | 0,5820 |
| Диагностические 400 записей из прежнего official test, с автоматическим ASR | 0,7000 | 0,6960 |

Official test уже использовался при оценке предыдущих версий. Поэтому строки с ним показывают повторную проверку, **не независимый новый тест**. Результат на 400 записях нельзя переносить на полный test. В обычном режиме приложение использует ASR, поэтому результат с эталонным текстом не является его измеренной end-to-end точностью.

## Код и локальные файлы

`app/gui*.py` содержит интерфейс; `app/recognizer.py`, `app/asr.py`, `app/embedding_features.py` — распознавание, транскрипцию и признаки; `app/honest_models.py` — обучение и оценку; `scripts/` — подготовку данных и офлайн-эксперименты. Это одно локальное модульное приложение, не набор микросервисов.

`config.json`, `datasets/`, `records/`, `cache/`, `reports/`, `exports/`, локальные модели и транскрипты не должны публиковаться. `.gitignore` пропускает только перечисленные исходники и один фиксированный модельный файл. Проверка `scripts/check_publication.py` сверяет состав индекса Git и SHA-256 этого файла перед коммитом; она не заменяет ручную проверку изменений.

Для тестов в окружении с установленными зависимостями:

```powershell
python -m unittest discover -s tests -v
python scripts/check_architecture.py
python scripts/check_publication.py --worktree
```

В этом репозитории нет аудиозаписей корпуса. Предобученный [emotion2vec+ base](https://huggingface.co/emotion2vec/emotion2vec_plus_base) загружается из источника авторов и не перепакован сюда. Опубликованные метрики не гарантируют такое же качество на других дикторах, микрофонах и условиях записи.
